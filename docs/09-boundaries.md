# 9. Границы данных, тайны и эксплуатация

## Где ходят данные

Шлюз соединяет четыре очень разных мира, и профили размещения записаны явно
([evals/deployment-profiles-v1.json](../evals/deployment-profiles-v1.json)):

| Поставщик | Размещение | Железо / среда | Граница данных | Доступность |
|---|---|---|---|---|
| `openai` | внешний API через ProxyAPI | управляется поставщиком | запрос уходит внешнему сервису | не зависит от вашей машины |
| `anthropic` | внешний API через ProxyAPI | управляется поставщиком | запрос уходит внешнему сервису | не зависит от вашей машины |
| `ollama` | локальная Ollama | Apple M4, Ollama 0.40.3 *(так записано в профиле)* | обработка на компьютере разработчика | пока запущены машина и Ollama |
| `vllm` | vLLM в Google Colab | NVIDIA T4 16 ГБ, vLLM 0.31.0 | через временный HTTPS-туннель в Colab | зависит от сеанса Colab и туннеля |

Про строку `ollama` стоит знать одну деталь: профиль в репозитории описывает Apple M4 и
Ollama 0.40.3, а замер квантизаций выполнялся на Windows/AMD64 с Ollama 0.40.13 — это видно
в `experiment.environment` файла
[local-quantization-comparison-v1.json](../artifacts/local-quantization-comparison-v1.json).
Профиль и артефакт расходятся, и такие расхождения следует замечать: числа производительности
относятся к той среде, где снят артефакт, а не к среде из описания.

Этот файл — не справка, а **политика**. Он отвечает на вопрос, который в реальных проектах
задают юристы и служба безопасности: «куда уходит текст обращения клиента». Ответ должен быть
в репозитории, а не в голове автора.

Практическое следствие для маршрутизации: политика
[routing-v1.json](../policies/routing-v1.json) содержит только `openai` и `anthropic`. Локальные
поставщики в бою недоступны (vLLM — временный туннель, Ollama — отдельное приложение), поэтому
они участвуют в экспериментах, но не в резерве. Резерв должен быть надёжнее основного варианта,
а не наоборот.

## Секреты

- Ключи лежат в `.env`, файл исключён из git ([.gitignore](../.gitignore)).
- В репозитории только шаблон [.env.example](../.env.example) с пустыми значениями и заготовками
  адресов.
- Ключи не попадают в ответы API и в артефакты: в отчётах фиксируются версии и хеши, а не
  переменные окружения.
- Отдельного хранилища секретов нет — для учебной машины это приемлемо, для сервера нет.

Существенная деталь, заметная при чтении [.env.example](../.env.example): адреса облачных
поставщиков направлены не в OpenAI и Anthropic напрямую, а в **ProxyAPI** — сторонний прокси-сервис.
Это ещё одна граница данных, о которой легко забыть: запрос проходит через третью сторону,
и тарифы ([evals/pricing-proxyapi-2026-10-02.json](../evals/pricing-proxyapi-2026-10-02.json))
тоже её, в рублях, а не в долларах поставщика.

## Конфигурация: как она читается

```python
missing = [name for name, value in values.items() if not value]
if missing:
    raise RuntimeError("Не заполнены переменные окружения: " + ", ".join(missing))
```

[app/config.py](../app/config.py#L38-L42)

Читается всё и сразу, при импорте модуля, и любая пустая переменная останавливает приложение.
Плюс — «падать рано»: неверная конфигурация не пропустит ни одного запроса. Минусы конкретны:

1. **Обязательны неиспользуемые переменные.** Даже если вы работаете только с OpenAI, нужны
   ключи и адреса vLLM — иначе приложение не поднимется. Причина: все одиннадцать переменных,
   которые читает [app/config.py](../app/config.py#L25-L37), проверяются одним списком, а
   провайдеры создаются все сразу
   ([app/api/routes/generation.py](../app/api/routes/generation.py#L33-L80)).
   Двенадцатая переменная шаблона, `VLLM_GPU_PROFILE`, не читается кодом вообще — она осталась
   как документация среды.
2. **Импорт имеет побочные эффекты.** `load_settings()`, создание четырёх HTTP-клиентов и чтение
   политики происходят при импорте роутера. Юнит-тест, импортирующий `app.api.routes.generation`,
   потребует полного `.env`.
3. **Правка конфигурации требует перезапуска.** Ничего не перечитывается на лету — включая
   политику маршрутизации.

Для замороженного учебного проекта это осознанно оставлено как есть: тема «настройки
и жизненный цикл приложения» видна именно в таком виде, а исправление описано в
[docs/10-exercises.md](10-exercises.md).

## Чего нет: список эксплуатационных пробелов

| Пробел | Риск | Что понадобилось бы |
|---|---|---|
| Нет аутентификации клиентов | любой, кто достучался до порта, тратит ваш бюджет | API-ключ шлюза, проверка заголовка |
| Нет ограничения частоты и квот | один клиент выест лимит поставщика | лимитер, бюджеты по ключу |
| Нет журналов и метрик | нельзя ответить «почему вчера было медленно» | структурные логи, счётчики, трассировка |
| Нет идентификатора запроса | ошибку клиента не сопоставить с логом | `X-Request-ID` и передача вниз |
| Нет TLS | трафик открытым текстом | терминация на прокси/ingress |
| Нет потоковой выдачи | клиент ждёт весь ответ | SSE + `RoutingState.output_started` |
| Нет кеша | повторные одинаковые запросы платные | кеш по хешу запроса |
| Нет проверки здоровья поставщиков | отказ обнаруживается запросом | периодические пробы, исключение из кандидатов |
| Нет тестов | регрессии ловятся глазами | pytest на домен и адаптеры с фейками |
| Один процесс, без graceful shutdown | теряются запросы при перезапуске | ASGI-сервер с воркерами, корректное завершение |

Ни один из пунктов не мешает использовать проект как учебный материал, и все они перечислены
в заданиях на развитие ([docs/10-exercises.md](10-exercises.md)).

## Как запускать безопасно (для этой конфигурации)

1. Слушайте только `127.0.0.1` (по умолчанию `uvicorn` так и делает, если не указать иное).
2. Не коммитьте `.env`, не пересылайте его в чатах и issue.
3. Помните, что порт `8001` выбран не случайно: скрипты экспериментов обращаются именно к нему
   (`GATEWAY_URL` в [scripts/](../scripts)). Запуск на другом порту потребует правки скриптов.
4. Перед закрытием ноутбука выгрузите локальные модели (`keep_alive: 0`), иначе Ollama занимает
   память после работы ([app/evaluation/ollama_benchmark.py](../app/evaluation/ollama_benchmark.py#L33-L45)).
5. Для vLLM помните, что туннель Colab живёт минуты-часы. Переменные `.env` под него придётся
   обновлять, иначе `vllm` будет отвечать ошибкой недоступности.

## Вопросы для самопроверки

1. Текст обращения клиента ушёл в `openai`. Чьи ещё стороны его увидели и где это записано?
   <sub>Кроме OpenAI — прокси ProxyAPI. Записано в профилях размещения (граница данных) и в
   адресах `.env.example`.</sub>
2. Почему `vllm` в реестре возможностей помечен как проверенный, но отсутствует в политике?
   <sub>Возможности и маршрут — разные вещи. vLLM проверяли в сеансе Colab (возможность
   подтверждена), но как постоянный резерв он непригоден из-за временного туннеля.</sub>
3. Что произойдёт с приложением, если удалить `VLLM_API_KEY` из `.env`, хотя vLLM не используется?
   <sub>Оно не запустится: `load_settings()` бросит `RuntimeError` с перечнем пустых переменных
   ([app/config.py](../app/config.py#L38-L42)).</sub>
4. Как убедиться, что ключи не попали в артефакты оценок?
   <sub>В отчётах фиксируются `code_version`, хеши файлов, версия Python и адрес шлюза — не
   переменные окружения. Проверяется поиском по `artifacts/` перед коммитом.</sub>
