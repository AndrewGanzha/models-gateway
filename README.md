# Model Gateway — учебный LLM-шлюз

Учебный проект для подробного изучения того, как устроен **шлюз (gateway) над языковыми моделями**:
единый интерфейс к разным поставщикам, реестр возможностей, нормализация ошибок, маршрутизация
с резервом и измерение качества решений на данных.

> **Статус: заморожен (архив).** Версия `0.1.0`, тег `v0.1.0-frozen`, дата консервации 2026-11-25.
> Код и данные больше не развиваются — проект оставлен как законченный учебный материал.
> Правила консервации, инвентарь и список намеренно не сделанного — в [ARCHIVE.md](ARCHIVE.md).

---

## Зачем этот проект

Шлюз над LLM — это слой между приложением и десятком несовместимых API. Приложение хочет
«дай ответ на сообщения», а не «разберись, чем `responses.create` отличается от
`messages.create`, и что делать с 429». Проект воспроизводит этот слой целиком, но в размере,
который можно прочитать за вечер: около 1 200 строк Python в самом шлюзе (плюс 700 — скрипты
экспериментов), четыре настоящих поставщика, один HTTP-интерфейс.

Проект специально построен так, чтобы **каждый принцип был виден в коде, а не только в тексте**:

| Принцип | Где смотреть | Что видно |
|---|---|---|
| Единый контракт вместо зоопарка API | [app/providers/base.py](app/providers/base.py), [app/domain/models.py](app/domain/models.py) | `Protocol` из 3 строк и одна модель запроса/ответа на всех |
| Изоляция поставщика | [app/providers/](app/providers) | Четыре адаптера, каждый знает только свой SDK |
| Реестр возможностей | [app/gateway/model_registry.py](app/gateway/model_registry.py), [app/domain/capabilities.py](app/domain/capabilities.py) | «заявлено» отделено от «проверено» |
| Нормализация ошибок | [app/domain/errors.py](app/domain/errors.py) | `retryable` — свойство ошибки, а не ветка в обработчике |
| Маршрутизация как данные | [policies/routing-v1.json](policies/routing-v1.json), [app/gateway/routing.py](app/gateway/routing.py) | Политика в JSON, а не в `if` |
| Резерв с ограничениями | [app/domain/routing.py](app/domain/routing.py#L16-L27) | Переключение запрещено после начала ответа |
| Решение по данным, а не по вкусу | [decisions/routing-v1.md](decisions/routing-v1.md), [evals/](evals), [artifacts/](artifacts) | Порядок поставщиков выведен из измерений |

## Быстрый старт

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/).

```bash
uv sync                        # поставит зависимости из uv.lock
cp .env.example .env           # затем заполните значения в .env
uv run uvicorn main:app --port 8001
```

Проверка, что поднялось:

```bash
curl http://127.0.0.1:8001/health
# {"status":"ok"}

curl http://127.0.0.1:8001/models
# массив из четырёх описаний: provider, model и четыре возможности с полем verified
```

Интерактивная документация API: <http://127.0.0.1:8001/docs>

### Переменные окружения

Файл `.env` **не хранится в репозитории** (он в [.gitignore](.gitignore)) — ключи у каждого свои.
Из двенадцати переменных [.env.example](.env.example) обязательны одиннадцать: настройки читаются
целиком при импорте и падают, если хоть одна пуста
([app/config.py](app/config.py#L38-L42)). Двенадцатая, `VLLM_GPU_PROFILE`, кодом не читается —
это только описание среды в шаблоне. Ключа Ollama в списке нет и не нужно: локальный сервер
не требует аутентификации. Итог: обязательны и адреса vLLM, даже если вы работаете только
с OpenAI. Это сознательное решение «падать рано» — и, одновременно, главный бытовой недостаток
проекта, подробнее в [docs/09-boundaries.md](docs/09-boundaries.md).

## Как выглядят запросы

### Прямой вызов поставщика: `POST /generate?provider=openai`

Запрос и **реальный** ответ этой конфигурации:

```bash
curl -X POST 'http://127.0.0.1:8001/generate?provider=openai' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "openai/gpt-6-luna",
    "messages": [
      {"role": "system", "content": "Отвечай одним словом."},
      {"role": "user", "content": "Столица Франции?"}
    ],
    "max_output_tokens": 20
  }'
```

```json
{
  "provider": "openai",
  "model": "openai/gpt-6-luna",
  "text": "П",
  "usage": {"input_tokens": 23, "output_tokens": 20, "total_tokens": 43},
  "finish_reason": "max_output_tokens"
}
```

Лимит в 20 токенов оборвал ответ — и это ровно то, чему учит проект: `finish_reason`
часть контракта, а не украшение. Приложение обязано различать «модель закончила мысль»
и «модель не успела».

### Маршрутизация: `POST /generate/auto`

Здесь модель выбирает не клиент, а политика, и виден весь путь попыток:

```json
{
  "route_version": "routing-v1",
  "selected_provider": "openai",
  "attempts": [{"provider": "openai", "status": "completed", "error": null}],
  "result": {
    "provider": "openai",
    "model": "openai/gpt-6-luna",
    "text": "тест",
    "usage": {"input_tokens": 12, "output_tokens": 6, "total_tokens": 18},
    "finish_reason": "completed"
  }
}
```

`attempts` — журнал маршрута: при отказе первого поставщика в массиве появятся две записи,
и клиент увидит, что его запрос спасся не бесплатно (потерянная задержка), но и не молча.

## Что показали измерения

Коммит фиксирует не только код, но и числа, на которых основан выбор маршрута
(подробный разбор — [docs/08-evaluation.md](docs/08-evaluation.md)).

Сравнение внешних моделей на наборе из 8 обращений,
[artifacts/model-comparison-v1.json](artifacts/model-comparison-v1.json):

| Поставщик | Модель | Точность | Средняя задержка | Вход/выход токенов | Оценка стоимости |
|---|---|---|---|---|---|
| openai | `openai/gpt-6-luna` | 8/8 = 1.00 | 2 171 мс | 684 / 205 | 0,0513 ₽ |
| anthropic | `anthropic/claude-haiku-4-5` | 8/8 = 1.00 | 677 мс | 1 064 / 34 | 0,3640 ₽ |

При равной точности основным поставщиком выбран более дешёвый, резервным — более быстрый.

Сравнение квантизаций одной локальной модели,
[artifacts/local-quantization-comparison-v1.json](artifacts/local-quantization-comparison-v1.json):

| Квантизация | Вес в VRAM | Точность | Средняя задержка | Токенов/с | Холодный / тёплый старт |
|---|---|---|---|---|---|
| `Q4_K_M` | 693 МБ | 6/8 = 0.75 | 24,9 мс | 288,7 | 1 876 мс / 20,6 мс |
| `F16` | 1 456 МБ | 4/8 = 0.50 | 34,8 мс | 164,1 | 2 872 мс / 31,9 мс |

Более точная квантизация оказалась **хуже** на этом наборе. Это не парадокс, а урок о размере
выборки: на восьми примерах разница в один-два ответа — шум, и вывод «F16 хуже» делать нельзя.
Учебная ценность именно в этом: измерительный стенд отделён от кода шлюза, поэтому сомнительный
результат видно как сомнительный, а не как «настройку, которую уже вкатили в прод».

## Известные особенности

Учебные проекты выглядят честнее с перечисленными швами. Эти места **сознательно не исправлены**
при консервации (см. [ARCHIVE.md](ARCHIVE.md)):

1. **Конфигурация читается при импорте.** [app/api/routes/generation.py](app/api/routes/generation.py#L33-L85)
   создаёт клиентов и читает `.env` на уровне модуля. Нет нужды в поставщике — но без его
   переменных приложение не поднимется, а тестировать станет тяжело.
2. **`httpx2` не объявлен в зависимостях.** [pyproject.toml](pyproject.toml) перечисляет
   `anthropic`, `fastapi`, `openai`, `python-dotenv`, тогда как код импортирует `httpx2`
   напрямую ([app/providers/ollama_provider.py](app/providers/ollama_provider.py#L3)). Работает,
   потому что `httpx2` притягивается транзитивно, но прямая зависимость должна быть объявлена явно.
3. **Ключи, а не аутентификация.** У самого шлюза нет проверки клиента: любой, кто достучался
   до порта, тратит ваш бюджет. Годится только для `127.0.0.1`.
4. **Нет потоковой выдачи, кеша и повторов внутри адаптера.** `streaming` в реестре честно помечен
   `unknown` — то есть «не реализовано и не проверено», а не «сломано».
5. **Набор для оценки крошечный** — 8 обращений и один разработческий сплит. Для решений о
   качестве нужен отдельный тестовый сплит и на порядок больше данных.
